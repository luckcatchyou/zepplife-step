# Zepp Life 步数同步工具

一个面向个人使用的 Zepp Life 数据提交页面，可在网页、本地服务、iOS 快捷指令或定时脚本中提交当天的目标步数。

> [!WARNING]
> 本项目使用 Zepp Life 的兼容接口，并非官方客户端。接口可用性、账号状态、设备状态和微信侧同步均可能变化。接口返回成功仅表示 Zepp 侧接受了请求，不能保证微信运动一定展示。

## 先看这一段：第一次使用怎么做

1. 在 **Zepp Life（原小米运动）** App 中使用邮箱注册，并为该账号设置独立登录密码，登录后点我的，第三方接入，绑定需要修改步数的App。
2. 部署项目或在电脑上启动本地服务，打开项目网页。
3. 输入 Zepp Life 账号和密码。账号会自动记住，密码不会保存（可交给浏览器密码管理器自动填充）。
4. 填写目标步数，范围是 `1` 到 `98800`；留空会随机生成 `18000` 到 `26000` 步。
5. “同意注册测试设备”默认已勾选，保持即可。它只在该账号确实没有任何可用设备时才会真正注册，注册成功后后续不再触发。
6. 点击“立即修改步数”，等待结果。成功后先在 Zepp Life 官方 App 中确认数据，再等待微信运动的官方同步。若不成功可以多试几次，如果还是不行，更换账号也不行，请提交issue。



---

## 项目能做什么

- 使用当前填写的 Zepp Life 账号登录并提交当天步数。
- 自动查询当前账号的已启用设备；找到可用设备时直接使用。
- 网页默认同意在账号没有可用设备时注册并验证一个测试设备（注册后回读确认启用才继续）。
- 支持网页操作、`POST /api/step` 接口、iOS 快捷指令和本地运行。
- 不依赖 npm 第三方包，仅使用 Node.js 内置的 `https` 和 `crypto` 模块。
- 每次提交都会重新按当前账号登录；网页不会缓存或回传 Zepp 的 `app_token`、`user_id`，切换账号不会串号。
- 只在浏览器本地记住账号；密码不写入 `localStorage`、`sessionStorage`，也不缓存任何 Zepp token。

## 使用前准备

| 需要准备 | 说明 |
| --- | --- |
| Zepp Life 账号 | 支持邮箱或手机号。项目只适用于 **Zepp Life**，不适用于 Zepp（Amazfit 跃我）账号体系。 |
| 独立登录密码 | 使用在 Zepp Life 中设置的账号密码，不是微信登录授权。 |
| 可用设备（推荐） | 已在官方 App 绑定且启用的设备会被优先使用。 |
| Node.js 18+（本地运行时） | Vercel 部署不需要在本机安装依赖；本地运行推荐使用当前 LTS 版本。 |

不要把自己的账号、密码、请求内容或部署地址交给不可信的人。项目本身不保存密码，但你的部署平台和网络环境仍应由你自己掌控。

## 方式一：部署到 Vercel

适合希望通过网址随时使用的人。

1. 打开 [Vercel](https://vercel.com)，使用 GitHub 账号登录。
2. 选择 **Add New → Project**。
3. 从 GitHub 中选择本项目仓库并导入。
4. 保持默认配置，点击 **Deploy**。
5. 部署完成后，打开 Vercel 提供的网址即可使用。

之后仓库有更新时，Vercel 会自动重新部署。打开网页前刷新一次，确保加载最新版本。

## 方式二：部署到 Cloudflare Pages

适合希望通过网址随时使用，并且不想用 Vercel 的人。后端由 Pages Functions 提供，接口路径同样是 `/api/step`。

1. 打开 [Cloudflare 控制台](https://dash.cloudflare.com)，进入 **Workers & Pages → Create → Pages**，连接 Git 仓库。
2. 构建设置按下表填写：

   | 配置项 | 值 |
   | --- | --- |
   | 框架预设 | `无` / `None` |
   | 构建命令 | `npm run build:pages` |
   | 构建输出目录 | `dist` |
   | 根目录 | `/` |

   **部署命令**和**预览命令**保持默认即可（本项目没有编译步骤，`dist` 里只生成 `index.html`）。
3. 点击 **Save and Deploy**。之后每次推送代码会自动重新部署。

注意事项：

- `functions/` 目录必须留在仓库根目录，它不受构建输出目录影响，Pages 会自动把它部署成接口。
- 不要把仓库根目录直接当输出目录，否则 `api/`、`lib/`、`server.js` 会被当成静态文件公开下载。
- 兼容日期写在 `wrangler.toml`（`2026-10-05`），用于启用 `node:crypto`；如需在后台改，不要调早于 `2026-08-04`。
- Cloudflare 免费计划对单次请求的 CPU 时间有限制。登录失败时会串行尝试多个节点，偶发偏慢或超时是正常的，稍后再试即可。

本地预览 Cloudflare 版本（需要 Node 18+，会临时下载 wrangler）：

```bash
npm run dev:pages
```

## 方式三：在电脑上本地运行

适合先测试，或不想部署到云端的人。

1. 在项目目录打开终端。
2. 启动服务：

   ```bash
   node server.js
   ```

3. 浏览器打开 [http://localhost:3000](http://localhost:3000)。
4. 需要用手机访问时，确保手机和电脑在同一局域网，然后访问 `http://电脑局域网IP:3000`。如无法访问，检查电脑防火墙是否允许局域网访问 3000 端口。

停止服务时，在终端按 `Ctrl + C`。

## 网页操作教程

### 1. 填写账号和密码

- **Zepp Life 账号**：填写邮箱或手机号。手机号未带国家区号时，会按中国大陆手机号处理。提交后会自动记住，下次打开页面自动回填。
- **密码**：填写 Zepp Life 的独立登录密码。密码不会保存在浏览器本地存储中，页面也没有“记住密码”选项；需要自动填充请使用浏览器自带的密码管理器（密码框已声明 `autocomplete="current-password"`）。

### 2. 填写目标步数

可直接输入数字，也可以使用页面上的快捷步数按钮。输入范围为 `1` 到 `98800`；留空则由服务端随机生成一个 `18000` 到 `26000` 的值。

### 3. 关于“同意注册测试设备”

该选项默认勾选，一般保持默认即可。提交时项目会先读取当前账号的已启用设备，**只有确实一个都没有**时，才会注册一个虚拟设备并回读确认启用。注册成功后，后续提交会直接读到它，不会再重复添加。

如果不想让项目改动你的设备列表，取消勾选即可；此时若账号没有可用设备，会返回“未找到可用的 Zepp 设备”。

### 4. 看懂结果

成功提示会显示本次输入的账号、步数和北京时间。它表示 Zepp 数据接口接受了本次提交。

这不是微信运动已更新的承诺。若微信没有变化，请先在 Zepp Life App 检查对应账号的设备与微信运动授权状态，然后等待官方同步完成。

### 5. 多账号依次操作

当前每次点击提交都会重新按输入框中的账号密码登录。因此可以在同一页面依次操作多个账号：每次改完账号后，同时填入该账号的密码和目标步数，再提交即可。

页面载入时会清除浏览器中残留的 Zepp token，确保不会串号。

## API 与 iOS 快捷指令

推荐使用 `POST`，不要用 `GET` 传密码，因为 URL 可能被浏览器历史、代理或日志记录。

### POST 请求

```http
POST https://你的域名/api/step
Content-Type: application/json

{
  "user": "your-account@example.com",
  "password": "你的ZeppLife密码",
  "steps": 23888,
  "allow_virtual_device": false
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `user` | 是 | Zepp Life 邮箱或手机号。`account` 也可作为别名。 |
| `password` | 是 | Zepp Life 独立登录密码。`pwd` 也可作为别名。 |
| `steps` | 否 | `1` 到 `98800` 的整数；不传或留空时随机生成。`step` 也可作为别名。 |
| `allow_virtual_device` | 否 | 默认 `false`。仅在允许为当前账号注册测试设备时传 `true`。网页表单默认勾选，即按 `true` 提交。 |

成功响应示例：

```json
{
  "code": 200,
  "success": true,
  "message": "Zepp 数据已提交（微信展示仍取决于官方同步）",
  "data": {
    "account": "your-account@example.com",
    "steps": 23888,
    "date": "2026-09-26",
    "time": "2026-09-26 18:50:00"
  }
}
```

### iOS 快捷指令设置

1. 新建快捷指令，添加“获取 URL 内容”。
2. URL 填写 `https://你的域名/api/step`。
3. 方法选择 `POST`，请求正文选择 `JSON`。
4. 添加 `user`、`password`、`steps`、`allow_virtual_device` 四个字段。
5. 将 `allow_virtual_device` 设为布尔值 `false`；只有确实需要注册测试设备时才改为 `true`。
6. 运行一次并查看返回的 JSON，确认 `code` 为 `200` 后再用于自动化。

接口同时支持 `GET`（参数放在 query 中），但请一律使用 `POST`，避免密码出现在 URL 里。

## 常见提示与处理

| 提示或现象 | 含义与建议 |
| --- | --- |
| `Zepp Life 账号或密码错误` | 检查账号类型、邮箱/手机号和 Zepp Life 独立密码；不要使用微信授权密码。 |
| `登录节点均受限或异常` / `请求超时` | 可能是网络波动、上游节点限流或暂时不可用，不等同于密码错误。不要连续高频重试；稍后再试，并确认官方 App 能正常登录。 |
| `未找到可用的 Zepp 设备` | 当前账号没有可读取的已启用设备。优先在官方 App 检查设备；仅在你接受修改设备列表时勾选测试设备选项。 |
| `添加测试设备失败` | 上游未接受设备注册，或未能确认设备已启用。不要反复提交；取消勾选后检查官方 App 的设备状态再试。 |
| 网页显示成功，微信运动未更新 | Zepp 接口已接受数据，但微信展示取决于官方同步与授权。检查 Zepp Life App 内对应账号的授权并等待同步。 |
| 两个账号会不会互相改到？ | 当前版本不复用浏览器 token；每次提交都使用本次输入的账号重新登录。 |

## 项目结构

```text
├── api/
│   └── step.js         # Vercel Serverless Function 入口（仅做 req/res 适配）
├── functions/
│   └── api/step.js     # Cloudflare Pages Function 入口（仅做 Request/Response 适配）
├── lib/
│   ├── zepp-core.js    # 业务逻辑：登录、设备检查与步数提交（两个平台共用）
│   ├── http-node.js    # Node/Vercel 网络层（原生 https）
│   ├── http-worker.js  # Cloudflare 网络层（原生 fetch）
│   └── template.js     # 上传数据模板
├── scripts/
│   └── build-pages.mjs # 生成 Cloudflare Pages 的静态输出目录 dist/
├── index.html          # 网页表单
├── server.js           # 本地运行服务
├── vercel.json         # Vercel 路由配置
├── wrangler.toml       # Cloudflare Pages 配置（兼容日期等）
└── package.json        # Node.js 项目配置
```

两个平台的接口行为完全一致，区别只在网络层：Vercel 用 `node:https`，Cloudflare 用运行时原生的 `fetch`（`redirect: 'manual'`，保证能读到登录接口的 302 `Location`）。

## 使用限制

- 只支持 Zepp Life 兼容接口，不支持 Zepp（Amazfit 跃我）账号体系。
- 只提交当天数据，日期按北京时间计算。
- 不保证微信运动展示结果，也不替代官方设备、账号或授权管理。
- 请合理使用，避免连续高频请求导致上游接口限制。
